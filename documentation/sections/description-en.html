The Behavioral Interoperability Testing Ontology (BITO) defines the core semantic elements required to represent behavioral interoperability requirements together with the execution evidence and assessment results associated with them. It models the considered use case and scenario, the implementation under test, the interacting actor or system, triggering interactions, expected state transitions, behavioral constraints, expected operational outcomes, observed execution evidence, trace evidence, validation results, and interoperability verdicts.

BITO is not intended to replace domain ontologies. Instead, it provides an additional behavioral interoperability testing layer that complements reused vocabularies. Concepts from SAREF and SAREF4ENER are reused where their semantics are suitable for representing devices, states, power sequences, slots, units, and related energy-domain structures. PROV-O is reused for actor, activity, and evidence-related modelling where appropriate, while OWL-Time provides temporal modelling support. BITO-specific classes and properties are introduced where the reused vocabularies do not provide the semantics required for behavioral interoperability testing.

The ontology represents both expected scenario behavior and observed execution evidence. Expected behavior is represented through scenarios, triggering interactions, expected state transitions, behavioral constraints, and expected operational outcomes. Observed behavior is represented through observed events, observed state changes, timestamps, trace evidence, and related execution information. Validation results connect the available execution evidence with the relevant behavioral constraints and may be associated with interoperability verdicts such as PASS, FAIL, or INCONCLUSIVE.

The current version includes representative instances for three Flexible Start scenarios. These instances demonstrate how expected behavior, observed execution evidence, trace evidence, behavioral constraints, and validation results can be represented using BITO. They are provided as validation examples of the modelling approach and do not restrict the ontology to the Flexible Start use case.
