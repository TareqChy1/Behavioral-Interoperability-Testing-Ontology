Interoperability testing often focuses on whether exchanged data is syntactically and semantically correct. However, interoperating systems may also need to be evaluated according to their behavior during execution. A system may exchange information using the expected structure and vocabulary while still failing to respect the expected order of interactions, timing conditions, state transitions, or operational outcomes. Behavioral interoperability testing therefore requires a representation that connects scenario-level expectations with evidence observed during execution.

The Behavioral Interoperability Testing Ontology (BITO) addresses this need by providing an ontology-based representation layer for behavioral interoperability testing. It represents the principal elements required to describe behavior in a considered use case or scenario, including the implementation under test, the interacting actor or system, triggering interactions, expected state transitions, behavioral constraints, expected operational outcomes, observed execution evidence, trace evidence, validation results, and interoperability verdicts.

BITO supports the explicit representation of the conditions that determine whether observed behavior conforms to expected scenario behavior. These conditions may concern states, transitions, ordering, timing, triggering interactions, and operational outcomes. Observed events, state changes, timestamps, ordering information, and trace evidence can be associated with the corresponding scenario expectations and validation results. Verdicts such as PASS, FAIL, or INCONCLUSIVE can then be represented as the outcome of the assessment.

The ontology is designed to be reusable and extensible. Existing ontology terms are reused where their semantics match the intended modelling purpose, while BITO-specific concepts are introduced where additional behavioral-testing semantics are required. In the current documentation, three Flexible Start scenarios are used as representative examples to demonstrate how expected behavior, observed execution evidence, trace evidence, behavioral constraints, and validation results can be represented within a common semantic structure.
